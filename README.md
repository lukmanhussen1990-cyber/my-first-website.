# Phantasy Codex Adventure

A compact top-down action RPG in the spirit of Game Boy Color-era *Final Fantasy
Adventure* and *Sword of Mana* — procedurally generated world, three weapons,
monsters that never stop coming, and a codex that remembers every beast you fell.

**The whole game is one file: [`index.html`](index.html).** No build step needed
to play, no dependencies, no external assets. Open it in a browser, or host it
anywhere that serves static files. It works on desktop and on phones.

---

## Playing

|             | Desktop                   | Mobile              |
| ----------- | ------------------------- | ------------------- |
| Move        | `WASD` / arrow keys       | left analog stick   |
| Attack      | `Space` / `J`             | big right button    |
| Dash        | `Shift` / `K`             | `DASH`              |
| Swap weapon | `1` `2` `3`, or `Q` / `E` | `SWAP`              |
| Codex       | `Tab`                     | book icon           |
| Pause       | `Esc`                     | pause icon          |

Attacks snap to a monster you are already roughly facing, so running past
something and swinging connects instead of whiffing.

### The loop

- **Explore.** Every run generates a fresh island: meadow, forest, mire, dunes,
  highlands, frostcaps and cinder wastes, ringed by ocean so there are no
  invisible walls. Shrines heal, obelisks temper a weapon a full tier, caches
  drop loot.
- **Fight.** Four **passive** creatures wander harmlessly until you strike one —
  then that one turns on you for good. Six **aggressive** species hunt: they
  prowl toward you at half pace from beyond their senses, then lock on and
  commit. **Elites** wear crowns, hit hard and pay triple.
- **Grow.** Kills feed XP. Each level offers one of three **boons** (common /
  rare / epic), weighted toward the weapon you actually use. Chain kills quickly
  for an XP multiplier. Periodic **surges** flood the area with monsters.
- **Die.** The run ends, and your level and total XP are published.

### The three weapons

| Weapon | Feel | Tier upgrades unlock |
| ------ | ---- | -------------------- |
| **Sword** | fast, forgiving arc | faster recovery → wider sweep → every 3rd hit is a full spin |
| **Spear** | committal, long, pierces | pierces 3 → lunges forward → impales everything in line |
| **Wand**  | ranged, seeking, thirsty | sharper homing → 2 bolts → 3 bolts → piercing sparks |

Stamina gates all of it. It trickles while you are mid-swing and comes back
properly the moment you let the pressure off — roughly 13 sword swings before
you need a breath.

## The shared leaderboard

When a run ends, the game publishes **level** and **total XP** (plus kills, time,
build title and world seed).

A single HTML file has nowhere private to keep a leaderboard, so the board talks
to **an HTTPS endpoint you configure** — a ChatGPT Sites page, a small worker, a
gist proxy, anything that speaks the contract below. Open **Leaderboard →
Setup** in game to point it at one.

With no endpoint configured the game still works: scores persist on the device,
and every run produces a shareable **run code** you can paste anywhere.

### Endpoint contract

```
POST <url>
  body: {board, name, level, xp, kills, time, build, seed}
  → store it

GET  <url>?board=<name>&limit=25
  → [{name, level, xp, build, time}, …]     (or {scores: [...]})
```

The endpoint must send permissive CORS headers, or the browser will block the
call. Failures degrade gracefully — the game never breaks because a board is
down, it says so and keeps the score locally. `test/board-test.mjs` contains a
~30-line reference implementation of this contract.

## How the artwork is made

There are no image files. Every sprite, tile, prop, weapon, projectile and UI
icon is **drawn pixel-by-pixel at boot** by a small rasteriser (`Pix`) with the
primitives a 16×16 sprite actually needs: ellipses, organic blobs, Bresenham
lines, ordered dithering, mirroring, automatic 1px outlining, and silhouette-
derived top-light/bottom-shadow rim shading that gives everything a consistent
light source.

The hero is assembled from parametric parts, so all four facings and the whole
walk cycle come out of one description — and his belt trim shifts colour as his
weapons are tempered. Monsters are shapes plus a palette, so recolouring one for
a different biome costs nothing. Ground tiles are generated in four variants
each and baked into 8×8-tile chunk canvases; water and lava animate live on top.

Sound is the same idea: a handful of oscillators and filtered noise bursts, no
audio files.

Total boot time, including generating every sprite: **under 300 ms**.

## Development

`index.html` is generated by concatenating the sources in `src/`:

```sh
./build.sh
```

A quick edit straight to `index.html` is fine, but changes belong in `src/` or
the next build will clobber them.

| Source | What lives there |
| ------ | ---------------- |
| `01-shell.html` | markup, CSS, HUD, touch controls, overlays |
| `02-core.js` | RNG, value noise, input, audio synth, display scaling |
| `03-art-core.js` | the `Pix` pixel rasteriser, palettes, tiles, props |
| `04-art-chars.js` | hero, monsters, weapons, icons, title banner |
| `05-world.js` | art registry, worldgen, collision, chunk cache |
| `06-defs.js` | weapon / boon / monster data |
| `07-play.js` | player, combat, monster AI, spawning, effects |
| `08-render.js` | draw order, sprites, particles, damage numbers |
| `09-ui.js` | leaderboard client, HUD sync, panels |
| `10-main.js` | game loop, state machine, wiring, boot |

### Tests

The suites under `test/` drive a real Chromium through Playwright:

```sh
npm install playwright
node test/test.mjs        # 66 checks — art, worldgen, combat, progression, UI, publish
node test/board-test.mjs  #  9 checks — stands up a reference endpoint, publishes, reads back
node test/soak.mjs        # 11 checks — 75s bot session: leaks, pool growth, frame rate
```

`test.mjs` runs everything against both a desktop and a mobile viewport, using
real keyboard and touch events rather than calling internals.

`window.PCA` exposes the game state and key functions for debugging and for
poking at a run from the console.
