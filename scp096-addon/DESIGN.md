# SCP-096 Bedrock add-on — design contract

Single source of truth for every file in this add-on. Everything below was
checked against Mojang's vanilla 1.21.0.3 samples (`/home/user/mojang/bedrock-samples`,
git tag `v1.21.0.3`) unless marked *(believed)*.

## 0. What the user asked for (acceptance list)

1. One `.mcaddon` that imports on Android/iOS, containing a Behavior Pack and a
   Resource Pack, linked by `manifest.json` dependencies, brand-new UUIDs.
2. Format versions valid for the user's game (**Minecraft Bedrock beta 1.21.0.26**,
   Android; see screenshot: "beta 1.21.0.26 … Android 14"). No experimental toggles.
3. Entity `scp:scp096`: very tall (2.5–3 blocks), thin, pale white, long arms, no
   hair, white eyes, big mouth. Custom `.geo.json`, `.png` texture, animations:
   idle (sitting + crying), walk, run (rage chase), scream/trigger. Sounds: crying
   when calm, screaming when triggered (real files, synthesised; built-in
   fallback documented).
4. Spawn egg "SCP-096 Spawn Egg", pale white with dark-grey spots, in the creative
   inventory (Nature tab), findable by searching "SCP" or "096".
5. Behaviour: calm (sits or walks slowly, cries, never attacks) → a player looks at
   its face (engine view/line-of-sight check) → it remembers that player as target
   → screams 3–5 s → runs very fast at the target, ignoring other players/mobs →
   breaks soft blocks in the way (doors, glass, leaves, wood; NEVER bedrock or
   obsidian) → kills target in 1–2 hits → when the target is dead it calms down →
   ~500 HP, strong knockback resistance, takes very little damage → never despawns.
6. English name "SCP-096"; `en_US.lang`; zero content-log errors/warnings.

## 2. Hard rules for every author

1. **Only use component names / fields / event-response keys that appear in the
   vanilla 1.21.0.3 corpus** (`grep` it) or in Microsoft's docs. If you must use
   something not proven by the corpus, say so in your report and justify it.
2. Strict JSON only: no comments, no trailing commas, UTF-8, no BOM, LF endings,
   2-space indent, final newline. (Vanilla files are sloppier than Bedrock tolerates in third-party packs.)
3. Bone / animation / state / sound names are case-sensitive and silently ignored
   when wrong — they must match this document exactly.
4. Use full Molang names (`query.`, `variable.`, `math.`) not the short forms.
5. Never touch a file you do not own (§3). Report needed changes instead.
6. Deliver evidence: commands run, output, what was verified against which vanilla file.

## 5. Entity state machine (the contract between BP, RP and script)

The engine tells the client which state it is in through **`minecraft:variant`**
(`query.variant` on the client, `EntityVariantComponent.value` in script):

| variant | state | what the player sees |
|---|---|---|
| 0 | `sit` | sits on the ground, hugging knees, hands over face, sobbing; cry sound |
| 1 | `walk` | upright, slow shuffle, hunched, crying (stationary = standing + sobbing) |
| 2 | `scream` | rooted; jaw wide open, head back, arms out, convulsing; scream sound; 3–5 s |
| 3 | `run` | rage sprint; arms thrashing forward; rage sound |

Component groups (BP, exact names):

* `scp096:calm` — `minecraft:lookat` (search_radius 64, `set_target: true`, `look_cooldown` 5, filter = other is `player` family — exactly the vanilla Enderman form) and `minecraft:on_target_acquired` → event `scp096:enrage` (target self).
  *Rationale:* the engine's lookat is the "player looks at its face" view/LOS test; vanilla Enderman wiring.
  Creative/spectator players do not trigger it (engine default). Testing must be in Survival.
* `scp096:pose_sit` — variant 0; collision box 0.9 × 1.5; movement 0; `minecraft:timer` 12–30 s → `scp096:begin_walk`.
* `scp096:pose_walk` — variant 1; collision box 0.7 × 2.8; movement ≈ 0.06 with `random_stroll` speed_multiplier ≈ 0.8, `random_look_around`; timer 8–20 s → `scp096:begin_sit`.
* `scp096:rage_scream` — variant 2; collision box 0.7 × 2.8; movement 0; no attack behaviour, no lookat; timer 3–5 s (random) → `scp096:begin_run`; target-lost safety → `scp096:calm_down`.
* `scp096:rage_run` — variant 3; movement ≈ 0.4 (≈17 blocks/s, player sprint 5.6); `melee_box_attack` (modern vanilla melee, same form as Enderman angry); `minecraft:break_blocks` with the soft-block list; door breaking as the vanilla zombie does; target-lost → `scp096:calm_down` (`on_target_escape` and/or environment_sensor `has_target == false`).

Base components (always): type_family, `minecraft:health` 500/500, `minecraft:knockback_resistance` 1.0,
`minecraft:attack` damage **300** (one hit kills anything but Resistance V / totem), `minecraft:follow_range` 64,
`minecraft:damage_sensor` reducing all damage to a small fraction (≈ ×0.1) — verify semantics against armadillo/frog vanilla JSON,
`minecraft:persistent`, `minecraft:nameable`, `minecraft:physics`, `minecraft:pushable`, `minecraft:movement.basic`,
`minecraft:navigation.walk` (`can_break_doors` true, no water pathing), `minecraft:jump.static`, `minecraft:behavior.float`,
`minecraft:collision_box` default 0.7 × 2.8, **no** `minecraft:despawn`, **no** `hurt_by_target` / `nearest_attackable_target` (target only ever comes from lookat ⇒ "ignores other players and mobs"), no spawn rules, no loot.

Events (BP, exact names): `minecraft:entity_spawned` (add `scp096:calm`, `scp096:pose_sit`), `scp096:begin_walk`, `scp096:begin_sit`,
`scp096:enrage` (remove calm/pose groups, add `scp096:rage_scream`), `scp096:begin_run`, `scp096:calm_down`
(remove rage groups, add `scp096:calm`, `scp096:pose_sit`). Events must be idempotent and must never leave two pose groups active.

Race to avoid: do **not** use `look_event`; enter rage from `on_target_acquired`
(the target is already set then) so "no target ⇒ calm" checks in the rage groups cannot fire early.

## 6. Model

* Front of the model is **−Z** (north), verified: vanilla pig head cube z∈[−14,−6], villager nose z∈[−6,−4].
* Bone naming mirrors vanilla: `right_*` sits at **−X**, `left_*` at **+X** (zombie `rightArm` pivot −5, `leftArm` +5).
* 16 px = 1 block. Standing height (sole → top of head) **44–46 px (2.75–2.9 blocks)**; width ≤ ~16 px with arms; thin limbs (2–3 px), long arms (finger-tips reach to ~knee/below), elongated hairless head.
* Bones (names/parents are fixed; pivots/cubes are the geometry author's design and are documented in the author's report):

```
root                      parent: -
  waist                   root
    torso                 waist
      head                torso
        jaw               head        (lower jaw, hinges open; interior painted dark)
      left_arm            torso   → left_forearm → left_hand
      right_arm           torso   → right_forearm → right_hand
    left_leg              waist   → left_shin
    right_leg             waist   → right_shin
```
* Geometry JSON: `visible_bounds_width` 4, `visible_bounds_height` 4, `visible_bounds_offset` [0, 1.5, 0].
* Eye/head centre at ≈ 2.4–2.6 blocks standing (engine eye height ≈ 0.85–0.9 × collision height 2.8) so
  the lookat gaze test lands on the head; sitting head centre ≈ 1.2–1.3 blocks (collision 1.5).
* The geometry author derives both `.geo.json` and the texture from ONE cube table (script) so UVs and
  painted features can never drift apart. Box-UV regions must not overlap and must stay inside 128×128.

## 7. Animation conventions (calibrated on vanilla files)

Bedrock animation `rotation` is `[x, y, z]` degrees, applied about the bone pivot in
parent space; order: X first, then Y, then Z (extrinsic; = `Rz·Ry·Rx`) *(believed — Java `rotationZYX` / Blockbench)*.
**Sign rules (verified by vanilla; see the Y correction below):**

* X: **negative = swing forward (−Z)**. `animation.zombie.attack_bare_hand` arms `−90`; cancan leg `−111`; riding arms `−36`.
* Y: **NOT negated** (CORRECTED after calibration on vanilla skeleton bow-hand geometry and head tracking): positive Y turns a forward (−Z) bone toward **−X**, i.e. toward the mob's right
  (right_* bones sit at −X; `query.target_y_rotation` is positive when the target is on the mob's right). Net rule: **X and Z are negated vs the right-hand rule, Y is standard**.
* Z: a bone on the **−X** side (right) swings **outward with positive Z**, on the **+X** side (left) outward with **negative Z**
  (armor stand default pose right arm Z=+10, left −10; evoker casting arms V: right +135, left −135).

`position` animation values are in model pixels, +Y up, −Z = forward. A bone's `position` adds to its pivot-relative position.
Calibrate any renderer on: zombie arms-forward pose (arms must appear in front of the face) and evoker casting (arms up/out in a V).

Sitting: lower everything with `root` position Y ≈ −(hip height − ground clearance) so the body rests on the ground; thighs forward/up, shins folded, forearms raised so hands cover the face.
Walking/running should be **distance driven** (`query.modified_distance_moved`, scaled by `query.modified_move_speed`) so a stationary walk-state entity stands still (sobbing only).

Animation controller `controller.animation.scp096.main`: one state per variant (`sit`, `walk`, `scream`, `run`),
transitions on `query.variant == N`, `blend_transition` 0.2–0.4 s, default state `sit`. `sound_effects` for the scream
on *state entry* (plays once per rage); crying via timeline `sound_effects` inside looping animations; rage sound on run.

Client entity scripts: `"animate": ["main"]` (+ optional head-look animation gated to non-sit states).

## 8. Sounds

OGG Vorbis, mono, 44.1 kHz, peak ≈ −3 dBFS, short fade in/out, no clipping, total shipped audio < ~600 KB.
Synthesised with numpy/scipy (voice-like source + formant filters + breath noise/tremolo) and encoded with `ffmpeg -c:a libvorbis`.
Variants: `cry1`, `cry2` (≈3–4 s sobbing wail), `scream1` (≈4 s, piercing, 400→1100 Hz sweep, distorted), `rage1` (≈2.5 s gritty screech/growl),
`hurt1` (short groan), `death1` (≈2 s descending wail). `sound_definitions.json` ids exactly as §4;
`sounds.json` maps `hurt`/`death` for `scp:scp096` (copy the exact structure of vanilla `resource_pack/sounds.json`).
Built-in fallback (documented in the guide, not shipped): `mob.ghast.moan`/`mob.ghast.scream`/`mob.enderman.scream`.

## 9. Script (`SCP096_BP/scripts/main.js`) — block clearing only

Purpose: while an `scp:scp096` has variant 3 (rage run), clear **soft** blocks in front of it so it can reach the target.
(`minecraft:break_blocks` handles blocks it collides with; the script clears the 3-high × 3-wide column ahead so pathfinding can open up.)

* ES module, `import { world, system } from "@minecraft/server";`, only API present in stable `server_1.11.0.json`.
* `system.runInterval` every 3–4 ticks; for each dimension (`overworld`, `nether`, `the_end`) `getEntities({ type: "scp:scp096" })`;
  skip if `world.gameRules.mobGriefing === false`; per-entity try/catch; unloaded chunks (`LocationInUnloadedChunkError`) ignored;
  heading = horizontal view direction; probe a box 3 wide × 3 high (feet-level up) × ~2.5 deep ahead; ≤ 12 breaks per pass.
* Allow-list by exact id / pattern: all wooden & metal doors, trapdoors, fence gates, wooden fences, planks, logs/wood/stems/hyphae (stripped too),
  wooden slabs/stairs, leaves (all, incl. azalea/mangrove/cherry), glass, glass panes, stained glass (+panes), tinted glass, wool, carpets,
  cobweb, ladders, scaffolding, bamboo, hay bale, signs. Every id MUST exist in
  `metadata/vanilladata_modules/mojang-blocks.json` (1.21.0.3).
* Deny-list checked first (defence in depth): bedrock, obsidian, crying obsidian, reinforced deepslate, barrier, command blocks, structure blocks,
  jigsaw, end portal/frame/gateway, portal, light block, border, allow/deny, netherite block, ancient debris, respawn anchor, any chest/container.
* Breaking = `dimension.runCommand("setblock x y z air destroy")` style (drops + particles) or `block.setType` — author decides, must validate command syntax against `metadata/command_modules`.
* Must degrade silently: no exceptions, no per-tick logging.
