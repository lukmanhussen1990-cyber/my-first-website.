# Parasite Apocalypse Survival — implementation spec

This file defines the contracts every part of the add-on must follow. If code disagrees with it, fix the code or update this spec everywhere the change applies.

### Entities
| id | role | base vanilla look |
|---|---|---|
| `pas:parasite` | crawler; replicates | original model from the reference image |
| `pas:infected_villager` | from villager / villager_v2 / wandering_trader | villager_v2 geometry + vanilla villager textures + infection overlay |
| `pas:infected_cow` | from cow / mooshroom (variant 0 cow, 1 red mooshroom, 2 brown mooshroom) | cow geometry + vanilla texture + overlay |
| `pas:infected_pig` | from pig | pig |
| `pas:infected_sheep` | from sheep (`pas:set_color_<0..15>`, `pas:set_sheared`) | sheep |
| `pas:infected_chicken` | from chicken | chicken |
| `pas:infected_human` | spawned where an infected player died | humanoid/zombie geometry + steve texture + overlay |

Every horde entity:
* `type_family` includes `pas_horde`, `monster` and `mob`. The parasite also has `pas_parasite` and `arthropod`; infected creatures have `pas_infected` and `pas_infected_<species>`. **Do not** add vanilla species families such as `villager` or `cow`.
* `is_spawnable: false`, `is_summonable: true`, `minecraft:persistent` (never despawns), `minecraft:nameable`.
* **Component group `pas:hunting`** holds all targeting and combat AI. **Component group `pas:dormant`** holds a frozen state (no movement or targeting; may keep `look_at_player`).
* Events:
  * `minecraft:entity_spawned` adds `pas:hunting`.
  * `pas:become_dormant` removes `pas:hunting` and adds `pas:dormant`.
  * `pas:become_active` reverses that.
  * Optional: `minecraft:entity_born` and `minecraft:entity_transformed`, which behave like `entity_spawned`.
* Infected creatures with baby forms have `pas:make_baby`. It adds a baby group with `minecraft:is_baby`, `minecraft:scale` 0.5 and halved collision, and **no** `ageable`, so they stay babies.
* Variant events (append the number):
  * `pas:infected_villager`: `pas:set_variant_<0..14>` (profession index, same order as vanilla villager_v2 `query.variant`), `pas:set_mark_<0..6>` (biome, vanilla `mark_variant`) and `pas:set_skin_<0..5>`.
  * `pas:infected_cow`: `pas:set_variant_<0..2>`.
  * `pas:infected_sheep`: `pas:set_color_<0..15>` and `pas:set_sheared`.
* `pas:parasite` has `pas:born`, which spawns the offspring with a birth flourish (optional visual only).
* Damage: `minecraft:damage_sensor` cancels any damage whose source is family `pas_horde` (no friendly fire).
* **Targeting** (`minecraft:behavior.nearest_attackable_target`, `must_see` false, `reselect_targets` true, ~`within_radius` 24), filter **all_of**:
  * any_of other `is_family`: `player`, `villager`, `wandering_trader`, `cow`, `mushroomcow`, `pig`, `sheep`, `chicken`
  * other `is_family` `!=` `pas_horde`
  * other `has_tag` `!=` `pas_incubating`
  * other `has_tag` `!=` `pas_infected_player`
* `minecraft:behavior.hurt_by_target` excludes `pas_horde`.

### Tags, dynamic properties, events, sounds, particles
See `ids.js`. Notes:
* `pas_incubating` goes on vanilla mobs and players while their infection incubates.
* `pas_infected_player` goes on players in stage 2.
* `pas_dormant` mirrors the dormant component group so scripts can check it.
* Sounds are defined in `sound_definitions.json` with category `hostile` for creatures, `player` for torch/UI and `neutral` for the base. Entity sound events (ambient/hurt/death/step/attack) are wired in `sounds.json` `entity_sounds.entities`.
* Particles live in RP `particles/` with format_version `1.10.0`.

## 4. Scripts — shared library (`scripts/lib`)

Plain ES modules (`.js`) with `// @ts-check` and JSDoc types. `tsc --checkJs` against the exact typings must pass. Never let an exception escape an event handler or interval: wrap with `safe()`.

`lib/util.js` (infra) exports at least:
`safe(fn, label)`, `vec`, `add`, `sub`, `scale`, `dot`, `len`, `normalize`, `floorVec`, `center(blockLoc)`, `blockKey(dimId, loc)`, `parseBlockKey(key)`, `getDimension(id)`, `allDimensions()`, `safeGetBlock(dim, loc)` (returns undefined for unloaded or out-of-world), `isLoaded(dim, loc)`, `tell(player, msg)`, `actionbar(player, msg)`, `title(player, title, subtitle?)`, `playSound(dim, id, loc, opts?)`, `playSoundTo(player, id, opts?)`, `spawnParticle(dim, id, loc)`, `getHeld(player)` → `{stack, hand: "Mainhand"|"Offhand"}|undefined` (mainhand first), `setHeld(player, hand, stack|undefined)`, `consumeHeld(player, hand)` (no-op in creative), `isSurvivalLike(player)` (survival or adventure), `cardinalFromYaw(yaw)` → `"north"|"south"|"east"|"west"`, `giveOrDrop(player, stack)`.

`lib/store.js`: JSON world-dynamic-property store. Keys may hold > 32 KB; chunk transparently into `key`, `key#1`, `key#2`…. Exports `loadJSON(key, fallback)`, `saveJSON(key, value)` and `scheduleSave(key, getter)`, which saves at most once per 20 ticks.

`lib/items.js`: one central item-use dispatcher.
`registerItemHandler(ids, { onUse?(player, stack, ctx), onUseOn?(player, block, face, stack, ctx) })`.
* It subscribes to `world.afterEvents.itemUse`, `world.afterEvents.itemUseOn` and `world.beforeEvents.itemUseOn`. Before-events are deferred with `system.run`, and before-events must never modify the world.
* **Edge debounce:** a use is accepted only if the same player had no item-use event of any kind in the previous 6 ticks. Every event, accepted or not, refreshes that timestamp. Holding the button produces exactly one action, and a block tap that fires both itemUseOn and itemUse produces one action.

`lib/kit.js`: on `playerSpawn` (initialSpawn), if the player lacks property `pas:kit_v1`, give one of each: Tactical Torchlight, Luxury Base Spawner, Parasite Outbreak, Outbreak Control. Then set the property.

`main.js` imports and calls `initKit()`, `initTorchlight()`, `initHouse()` and `initOutbreak()`, each wrapped in `safe`. Each init subscribes its own events and is idempotent.

## 5. Tactical Torchlight (`scripts/torchlight/`)

* **Toggle:** a use while holding `pas:tactical_torchlight` replaces that stack in the same hand with `pas:tactical_torchlight_on`, and the reverse. The swap keeps nameTag and lore. Play `pas.torch.on`/`off` and show actionbar `Torchlight ON` or `Torchlight OFF`.
* **Real light:** every 2 ticks, for each player holding `pas:tactical_torchlight_on` in the main hand or offhand, raycast from `getHeadLocation()` along `getViewDirection()` up to 24 blocks with `dimension.getBlockFromRay` (ignore passable blocks and liquids as hits; fall back to manual stepping if it throws).
  * Put light anchors at three points along the beam: the **spot** (the air cell in front of the hit face, or the beam end) at level 15, a **mid** point at ~45% of the distance at level 13, and a **near** point about 2.5 blocks ahead at level 11.
  * Each anchor must be `minecraft:air` exactly (`block.typeId === "minecraft:air"`). If it isn't, search back along the ray, then the 6 neighbours, for an air cell. If none is found, skip that anchor. **Never** replace anything that is not air.
  * Light block: `BlockPermutation.resolve("minecraft:light_block", { block_light_level: N })` (verified state name for 1.21.0.26). As a fallback for newer builds, `minecraft:light_block_<N>`.
* **Ownership:** a global map `cellKey -> Set<playerId>` plus a per-player set. Only remove a cell when its last owner releases it, **and** only if the block there is still `minecraft:light_block` (a player may have replaced it). Place new anchors before removing stale ones to avoid flicker. Skip work when the anchor cells did not change.
* **Cleanup** releases all of a player's cells when:
  * the item is switched or the torch is turned off;
  * the player dies (`entityDie`);
  * the player leaves (`beforeEvents.playerLeave`, then deferred, and `afterEvents.playerLeave` by id);
  * the player changes dimension (`playerDimensionChange`, which uses `fromDimension`), or the per-tick check notices the dimension changed;
  * the script starts up.
* **Persistence:** every owned cell is stored in world property `pas:torch_cells` as `[[dimId,x,y,z],…]` via the store. On startup every stored cell is cleaned up. If its chunk is unloaded it stays in a pending list that is retried every 40 ticks until it can be cleared. Light blocks are never left orphaned after a crash or reload.
* Visual model: the attachable `pas:tactical_torchlight` / `pas:tactical_torchlight_on` with geometry `geometry.pas.tactical_torchlight`. The on-variant lens glows using an emissive material.

## 6. Luxury Base (`scripts/house/`, `tools/house/`)

* `tools/house/` (Python) holds the blueprint: two usable floors plus a roof, quartz + dark oak + large glass. It must include:
  * a balcony and stairs between floors;
  * 2 bedrooms with beds;
  * a living area, a kitchen (smoker/furnace/cauldron), storage (chests, barrels) and a crafting area (crafting table, furnace, blast furnace, stonecutter, anvil, loom, smithing optional);
  * interior lighting (lanterns, sea lanterns or glowstone);
  * functional doors.
* It emits:
  1. `addon/behavior_pack/structures/pas/luxury_base.mcstructure`: NBT little-endian, `format_version` 1, palette version 18153475, full state sets from `mojang-blocks.json`. Cells outside the house shape are `minecraft:structure_void`. Include `block_entity_data` for beds (colour) and chests (a few starter supplies), following the PocketMine 5.16 tile NBT layouts.
  2. `addon/behavior_pack/scripts/house/blueprint_meta.js` exporting `HOUSE = { structureId: "pas:luxury_base", size: {x,y,z}, entrance: {x, y, z}, entranceSide: "south", floorY, supportRatio: 0.8, buildSeconds }`. In canonical orientation the entrance is on the **south** (+z) side.
  3. Preview PNGs in `docs/images/` (per-floor plans and an isometric view).
  4. A validator that re-reads the `.mcstructure` with an independent parser and checks it against `mojang-blocks.json`.
* **Placement (script):**
  * Use the `pas:luxury_base_spawner` item on the top face of ground (`onUseOn`), or use it in the air with a raycast of up to 12 blocks to the ground.
  * Place the house so the entrance doorstep faces the player. Pick the `StructureRotation` that maps canonical south to the direction pointing back at the player.
  * Check every cell of the rotated bounding box above ground: it must be air or natural replaceable vegetation (short/tall grass, fern, flowers, dead bush, snow layer, vines and similar). No liquids.
  * At least `supportRatio` of the footprint cells directly below must be solid (not air or liquid).
  * The box must be inside the dimension height range, fully loaded, and not overlapping any in-progress build.
  * If blocked, show a clear message with the reason and the first blocking coordinate, and do not consume the item.
  * Place with `world.structureManager.place("pas:luxury_base", dim, origin, { rotation, animationMode: "Layers", animationSeconds: buildSeconds, includeEntities: false, waterlogged: false })`. If that throws, fall back to `dimension.runCommand("structure load pas:luxury_base x y z <rot> none layer_by_layer <secs> false true")`.
  * **Rotation direction:** do not trust an assumption. Before the first placement each session, calibrate with a tiny in-memory probe structure (`createEmpty` + `setBlockPermutation`) placed inside the already-verified empty volume. Read back the result, restore the cells to air, and cache the mapping. If calibration fails, fall back to the convention that `Rotate90` is clockwise when viewed from above.
  * Consume one item in survival after a successful start, then show progress and completion messages.

## 7. Parasite outbreak (`scripts/outbreak/`)

**Config** (world property `pas:config`). Default and range for each setting:

| setting | default | range |
|---|---|---|
| `replicationSeconds` | 30 | 10–300 |
| `incubationSeconds` (mobs) | 20 | 5–120 |
| `playerIncubationSeconds` | 45 | 10–300 |
| `populationCap` | 64 | 4–200 |
| `infectPlayers` | true | |
| `showHud` | true | |

**State** (world property `pas:outbreak`): `{ v:1, active, paused, generation, ticksToNext, epoch, purges: {"<epoch>": "cleanup"|"cure"}, stats: {births, infections, conversions, deaths} }`.

* **Start:** using `pas:parasite_outbreak` on a block spawns one `pas:parasite` on top of it, after a cap check.
  * If the outbreak is inactive it becomes active with `generation` 0 and `ticksToNext = replicationSeconds*20`. Show title "☣ PARASITE OUTBREAK ☣" and play `pas.outbreak.start`.
  * If it is already active the item adds another parasite.
  * Consume the item in survival.
  * The outbreak never starts any other way.
* **Main loop** runs every 20 ticks while active and not paused: `ticksToNext -= 20`, then process incubations, and save state at least every 100 ticks or on change.
* **Generation:** when `ticksToNext <= 0`, take a snapshot of every loaded, valid `pas:parasite`. Set `budget = populationCap - hordeCount()`. The first `min(snapshot, budget)` parasites each spawn exactly one offspring next to themselves, spread over ticks at ≤ 8 spawns per tick. Then `generation++` and `ticksToNext` resets. With no deaths and no cap, the counts go 1 → 2 → 4 → 8.
* `hordeCount()` = loaded entities with family `pas_horde` across all three dimensions **plus pending queued spawns**. The cap applies to reproduction, conversion and infected-human spawns alike.
* **Infection start:** handled in `world.afterEvents.entityHurt` when `damage > 0`, the outbreak is active and not paused, and the attacker is either a `pas_horde` entity or a player in stage 1 or 2. The target must be infectable and healthy:
  * infectable means its type is a key of `CONVERSIONS`, or it is a player in survival/adventure with `infectPlayers` on;
  * healthy means it has no `pas_incubating` or `pas_infected_player` tag and is not horde.
  * Then add tag `pas_incubating` and set `pas:inc_ticks`, `pas:inc_total` and `pas:inc_epoch=epoch`. Players also get `pas:stage=1`. Play the start sound and spawn spores. Players also get a title/actionbar warning.
* **Incubation tick** (every 20 ticks, loaded entities with tag `pas_incubating`):
  * If `inc_epoch < state.epoch`, the entity was purged: clear it.
  * Otherwise decrement and show feedback: spores every second, slowness on mobs, and for players an actionbar countdown plus nausea pulses.
  * At ≤ 0, mobs **convert** if `hordeCount() < cap`; otherwise they hold at 0 and show "dormant" feedback until room frees up.
  * At ≤ 0, players move to **stage 2**: remove `pas_incubating`, add `pas_infected_player`, apply recurring hunger and nausea pulses, and show the actionbar "☣ INFECTED — your attacks spread the parasite".
* **Conversion:**
  1. Capture origin data: villager `minecraft:variant`/`minecraft:mark_variant`/`minecraft:skin_id`, cow vs mooshroom red/brown, sheep `minecraft:color` and `minecraft:is_sheared`, `minecraft:is_baby`, nameTag.
  2. Spawn the mapped infected type at the same location and copy rotation.
  3. Trigger the variant, baby and sheared events, and set `pas:epoch`, `pas:origin` and `pas:origin_data`.
  4. Copy the nameTag, then `remove()` the original (no drops).
  5. Play burst particles and the convert sound. If paused, also make the new entity dormant.
* **Transmission:** infected creatures use the same entityHurt path, so any horde damage infects. Players in stage 1 or 2 infect whatever they damage. This produces chains such as parasite → villager → infected villager → cow → infected cow → pig.
* **Cooperation:** horde entities never target or damage each other, and their targeting skips tagged (infected) mobs and players.
* **Player death** while in stage 1 or 2, or killed by a horde entity: if `hordeCount() < cap`, spawn `pas:infected_human` at the death location with nameTag `Infected <name>`. Clear the player's infection (props, tags, effects). The respawned player is healthy.
* **Pause/Resume:**
  * Pause sets `paused`, sends `pas:become_dormant` and adds `pas_dormant` to all loaded horde entities. Timers and incubations freeze and no new infections start.
  * Resume reverses that.
  * Entities that load later are synced via `entityLoad` and a 5-second sweep.
* **Cleanup:**
  * Sets `epoch++` and `purges[epoch]="cleanup"`.
  * Removes all loaded horde entities and clears all incubations and player infections.
  * Sets the state to inactive with generation 0.
  * Entities that load later with `pas:epoch < epoch`, or vanilla mobs with `inc_epoch < epoch`, are handled lazily on load.
* **Cure:**
  * Sets `epoch++` and `purges[epoch]="cure"`.
  * Removes parasites and reverts infected creatures to their `pas:origin` type with best-effort origin data: villager profession via the vanilla `minecraft:become_<profession>` events, mooshroom `minecraft:become_brown` etc., baby where possible, and nameTag.
  * Clears all incubations and player infections and sets the outbreak inactive.
* **Save/reload:** all state lives in world and entity dynamic properties, tags and component groups, so it survives saving. On startup, rebuild in-memory caches from them. Timers resume from `ticksToNext` and the saved `pas:inc_ticks` values.
* **Controls (mobile UI):** using `pas:outbreak_control` opens an ActionFormData with:
  * a status body (active/paused/inactive, generation, parasites, infected, incubating, cap, next generation countdown);
  * buttons Pause/Resume, Settings (ModalFormData sliders and toggles with the ranges above), Cure everything (MessageFormData confirm), Clean up outbreak (confirm), Cure me (when infected), Close.
  * While the control is held, the actionbar shows a short live status if `showHud` is on.
  * Also available as `/scriptevent pas:outbreak <status|pause|resume|cleanup|cure|start>` (needs cheats).
* `outbreak/api.js` exposes `getState`, `getConfig`, `setConfig`, `startOutbreak(dim, loc, player?)`, `pause`, `resume`, `cleanup`, `cure`, `hordeCount` and `infect(entity, sourceEntity)` for the UI and tests.

## 8. Testing contract

* `tests/mock/` is a behavioural mock of the parts of `@minecraft/server` and `@minecraft/server-ui` that the add-on uses. It has:
  * a manual tick driver;
  * dimensions with sparse block storage and a configurable loaded region;
  * `BlockPermutation.resolve` validated against `mojang-blocks.json` (path from env `PAS_VANILLA_REF`, defaulting to the `$REF` path above; tests needing it skip with a message if it is missing);
  * entities with families from a type registry, tags, dynamic properties, health and components;
  * events with `fire()` helpers;
  * `structureManager` that parses our `.mcstructure`;
  * world serialisation and deserialisation for save/reload tests.
* `node --import ./tests/mock/register.mjs --test tests/` runs everything, and `npm test` wraps it. The mock is documented in `tests/mock/README.md`.
* `npx tsc -p tsconfig.json` type-checks `addon/behavior_pack/scripts/**/*.js` against the exact typings.
* `python3 tools/validate.py` cross-checks all JSON references against our packs plus vanilla `$REF`: geometry, textures, animations, render controllers, materials, sounds, particles, item icons, entity events and component groups, and lang keys.
* `python3 tools/build.py` merges fragments, validates, and writes `dist/ParasiteApocalypseSurvival.mcaddon` (a zip with top-level folders `Parasite Apocalypse BP/` and `Parasite Apocalypse RP/`).
